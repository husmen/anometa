Abstract

Factories need to catch defects, but defects are rare: often there is a handful of labelled examples, sometimes one. Can TabPFN-3.5, a foundation model for tables, turn a few labelled defect images into a useful detector, using only frozen features from a vision foundation model? Anometa encodes each image with a frozen DINOv3 vision transformer, compresses it to one table row, and lets TabPFN-3.5 classify new rows in context, with no gradient updates. On the 8 scenarios of MVTec AD 2, under a protocol that freezes the configuration on a dev split and evaluates it once on a held-out lock split, TabPFN reaches a lock AUROC of $tab1 with one labelled defect per scenario (logistic regression: $log1), and its probabilities have about half the balanced log loss. A good label-free novelty score ranks images just as well, so on this benchmark the frozen DINOv3 features do most of the work. A prototype that scores one row per image patch turns TabPFN into a defect-map generator that beats its own input maps on the dev split.

The name is anomaly + meta: meta-learning, as TabPFN learns each task in context, and a meta-framework not tied to one model or dataset. TabPFN-3.5 and MVTec AD 2, chosen for the Prior Labs TabPFN-3.5 hackathon, are the starting point (see the roadmap).

Method

One image becomes one table row: the DINOv3 global token and mean patch (compressed by PCA) plus two novelty numbers, the distances of the image's most unusual patches to their nearest normal patch.

TabPFN reads the rows of a few hundred normal images and k labelled defects as its context and predicts, in one forward pass, the probability that each new image is defective. There is no training and no tuning: fitting takes milliseconds.

TabPFN as a defect-map generator (prototype)

Each 16×16-pixel patch becomes a row (patch token, DINOv3 distance, PatchCore value and their 3×3 maxima), and TabPFN-3.5-Fast scores every patch. On the dev split of all 8 scenarios its maps beat the DINOv3 distance map by $tc2 (k = 2) and $tc5 (k = 5) AU-PRO@0.05. Dev only, 3 seeds, no frozen protocol yet.

Speed and reproducibility

  • TabPFN fits in about 5 ms; one scenario runs end to end in about 14 s on an RTX 3090 (2.1 min on an Apple M4 Pro, 9.8 min on a CPU).
  • Results match within 0.005 AUROC on the M4 Pro and within 0.001 on a CPU-only Ryzen.
  • Every run writes a manifest (git commit, dataset, split and config hashes, model revisions, licences, seeds, hardware), metrics and per-image predictions.

Limitations

  • Lock numbers use half of the public test set (7 defect scenes per scenario), so intervals are wide and the numbers are not directly comparable with the private test set.
  • Only PatchCore was tuned for pixel metrics (input size and coreset ratio, on dev); EfficientAD-S and our DINOv3 pipeline were not.
  • TabPFN maps exist only as a dev-split prototype.
